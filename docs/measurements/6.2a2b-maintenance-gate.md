# The maintenance share: the gate for a fourth thread, ingest latency and the digest's cost

Roadmap 6.2a2b; compaction design §4 and §3.2 step 2; Q-801, Q-1532, Q-1533. All figures are from one shared 4-core
cloud machine (a virtual machine, other work possibly running), not from the target hardware; device sync times are
a sleep in every sync, standing in for the device.

## The gate for a fourth thread

`scripts/maint-gate.sh <dir> --secs 60` (`log/examples/maint_gate.rs`), pinned to one core: 1,000 readings a second,
one per call, 64 KiB segments so that creation ahead and seals come often; once without a background task and once
with a task that encodes a block of 4,096 rows, writes one 128 KiB piece and syncs its file every 1 MiB, governed by
the default share for one core (0.15 of the core). Waits are from the writer handing the work over to `kvik-maint`
starting it. The samples are few (25 to 35 creations and 23 to 33 seals a run), so p99 is the largest.

The p99 delay a running task adds is one step's device call (2 ms against a bound of 10 ms on the minimal SSD row;
22 ms against 50 ms on the SD row): the gate passes and the task stays on `kvik-maint` (Q-1533). Commit latency with
the task is within noise of without it.

## The digest's cost

`kvik/src/durable/compact/tests.rs` `measure_the_digest_against_the_run` (`cargo test --release -p kvik --lib
measure_the_digest -- --ignored --nocapture`), one core, 40,000 facts of 100 series in four sealed segments, three runs
each; the digest is computed for the input and the output side of each fact.

| SHA-256 | Run, ns a fact | Digests, ns a fact | Share of the run |
|---|---:|---:|---:|
| with SHA instructions | 1,786 / 1,702 / 1,828 | 227 / 221 / 254 | 12.7 / 13.0 / 13.9 % |
| portable (`--cfg sha2_backend="soft"`) | 2,337 / 2,301 / 2,241 | 692 / 681 / 700 | 29.6 / 29.6 / 31.2 % |

It does not dominate: the digest stays SHA-256 (Q-1532).
