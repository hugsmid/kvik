# 6.1 Chunk encodings: size check against roadmap 2.1

Roadmap item 6.1 implemented the block bodies and column encodings of compacted chunks
([`format-chunk.md`](../format-chunk.md), crate `kvik-chunk`). This check encodes the data sets of
[2.1](2.1-chunk-encodings.md) with it and compares the size with the spike's "delta/decimal/RLE" candidate, the one
gate 2.3 carried into the format (it already compresses the XOR fallback with zstd).

```sh
cargo run --release -p encodings --example chunk_sizes -- --reps 5   # about 30 s
```

## Method
The spike's generator gives the same chunks as in 2.1. Each chunk is split into blocks of 4,096 rows and each block
encoded with `Block::encode`, then decoded and compared with its rows. A chunk's value kind maps to value type 1
(`f64`), 2 (decimal, at the shape's scale) or 4 (bool); generation 1; no `changed_at`. The chunk around the blocks is
roadmap 6.2's, so it is counted as the spike counts its own: 9 bytes per chunk, 20 per block and a 24-byte file
directory entry per chunk. "Overhead" adds the block prefix and column directory; "value" includes the value-type and
scale columns, "position" the generation and sequence. Encode and decode times are the median of 5 repetitions over
all blocks, one thread, in memory, on the machine of 2.1 (a laptop-class 12-core ARM64 CPU), at lowered priority.
Sizes are deterministic.

## Findings
- **Size matches 2.1.** Within 0.01 bytes per row of the spike on every data set: 0.2–0.5 % larger on the decimal
  sets, 0.6 % smaller on the non-decimal set. Against Parquet with ALP (2.1: 2.15, 1.83, 1.60 and 1.04 bytes per row)
  the own format stays smaller on all four, by 0.6 % on the `i64` set, where 2.1 found 1 %.
- **Where the bytes go.** Delta frames are byte-aligned (a LEB128 minimum, a width byte, padding to a byte), where the
  spike packed them into one bit stream; that costs up to about a byte per 128 values in each of `t`, sequence and
  value, the 0.004–0.008 bytes per row seen above. The value-type and generation columns add a few bytes per block.
  Exceptions take 10 bytes each against the spike's 76 bits, but only values that fit are delta-coded (the spike
  repeated the previous integer at each exception); on the non-decimal set, with many exceptions, the two
  balance slightly in favour of 6.1.
- **Speed is below the spike's** (2.1: 147–167 million rows per second to encode, 370–400 to decode). The encoder
  tries every candidate exponent and computes each payload length exactly, so that the choice is a stated rule (C.9);
  the decoder checks every payload and range and builds all columns of a block. Decoding at 130–180 million rows per
  second, one block holding an hour of one series takes about 25–30 µs. Faster decoding (a decoder of selected columns, wider
  unpacking) is left to the query work (roadmap 9.2) and confirmed at scale by 10.1.

Limits: as 2.1 (synthetic data, in memory and in cache, one thread); the chunk layout is estimated, not built.
