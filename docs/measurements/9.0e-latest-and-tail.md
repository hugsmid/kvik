# 9.0e Latest values and the tail on a year of seals

Roadmap item 9.0e: the budgets S1, S2, S3 and S13 of the query design's section 1, measured with
[`kvik/benches/read.rs`](../../kvik/benches/read.rs) (`cargo bench -p kvik --bench read`, Q-1052).

## The store

105,687 sealed segments (a year at the default five-minute seal interval is 105,120), one reading each, the 400
series in turn, 79 MB; then an open segment holding five minutes at 45 readings a second, one reading a batch
(13,500 batches). It holds a year's count of seals, not a year's bytes: a sealed segment at the home rate holds about
2.5 MB, which no figure here depends on except through the open segment, which is at full size. On the real file
system, 16 MiB segments.

recorded" waits for the hardware run of roadmap 9.2 (Q-1052).

each of the three runs (S1, S2: 50 runs; S3: 20; S13 empty poll: the mean of 50 polls, five times; S13 visibility:
60 readings). The design's figures are p99 targets.

## Against the targets

- **Met:** S2 in both columns; S13 visibility at both poll intervals; S13's empty poll in the writer's process;
  S1 with nothing written since, by its median (the worst of 50 is above it).
- **Missed on this machine, against the desktop column:** S1 after a write (Q-1007, Q-1055, until roadmap 9.0j);
  S3 and S13's empty poll of a reader process as first measured, both changed by the fix round (below).
- **S3 grew with the number of sealed segments** (about 1.7 µs a segment) because a reader's start listed `log/`, a
  defect against the design, fixed (Q-1053).
- **S13's empty poll** was 31–40 µs on about 1,100 sealed segments (Q-1017) and 64–111 µs here. No part of a poll
  depends on the number of sealed segments; the difference is the machine's wake-up cost on two days, not the log's
  age (Q-1054).

## After the fix round

Two engineering changes, measured on a store of 41,299 sealed segments built by the same harness (a store of a
year's count took longer to build than the round allowed; no figure below depends on the count, as the system
calls show), three runs on 2026-11-20, load average 0.4 to 1.9.

- **S3 (Q-1053).** A reader's start no longer lists `log/`: it finds the segment holding the position after the
  series directory's `through` by name (the mark's segment and the two before it, then a binary search over headers).
  A system-call trace of `kvik latest` shows two directory listings, `derived/` (one file per 256 segments) and
  `registry/`, 192 metadata calls in all, 36 opens and 32 reads; before, one listing of `log/` with 10,747 metadata
  calls at 10,669 sealed segments.
- **S13 (Q-1054).** A mark-only poll reads the mark through the handle its last full refresh opened: one positioned
  read, no open. The harness prints beside each poll figure a reference: a read of a small file by the standard
  library (open, read, close) after the same 21 ms sleep, the machine's cost of its first system calls after a wake.

| # | Shape | Median | Worst | Desktop target | Minimal target |
|---|---|---|---|---|---|
| S3 | a reader opened, one snapshot of 400, closed | 22.0, 27.3, 40.3 ms | 31.0, 37.7, 50.7 ms | ≤ 30 ms | ≤ 200 ms |
| S3 | `kvik latest` as a process (warm) | 25.5, 40.9, 55.0 ms | 32.3, 46.4, 61.3 ms | ≤ 30 ms | ≤ 200 ms |
| S13 | empty poll, a reader handle, `Tail` (mean of 50) | 41.4–45.4 µs | 47.8–50.0 µs | ≤ 50 µs | ≤ 200 µs |
| S13 | reference beside it: a small file read after the same sleep | 56.3–59.7 µs | 64.0–94.3 µs | — | — |
| S13 | empty poll, a reader handle, `Tail` and `Latest` of 400 | 72.7–77.0 µs | 73.8–90.4 µs | — | — |
| S13 | empty poll, the writer's process, `Tail` | 12.1–13.4 µs | 14.2–16.8 µs | ≤ 50 µs | ≤ 200 µs |

S3 rose from run to run because each run writes rounds of readings into the store's open segment and the series
directory is not written again within the runs (its cadence is 32 MiB or 15 minutes): the start's tail grew from the
built 2.6 MB to 5 MB. The first run is the design's stated case, every series with a reading in an open segment just
after a series directory; a store whose series directory is the full 15 minutes behind reads more tail (about
7.5 MB at the home rate, the design's 15 ms tail term). The process figure adds the binary's start, about 4 ms.

S13's poll is now below the reference read: the poll's work is one read of 4,224 bytes, under 2 µs back to back
(the 9.0e review's probe); what remains is what any first system call costs on this machine after a 21 ms sleep.
Whether 50 µs holds is for the desktop-class run of roadmap 9.2.
