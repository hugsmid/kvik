# 9.0e Latest values and the tail on a year of seals

Roadmap item 9.0e: the budgets S1, S2, S3 and S13 of the query design's section 1, measured with
[`kvik/benches/read.rs`](../../kvik/benches/read.rs) (`cargo bench -p kvik --bench read`, Q-1052).

## The store

105,687 sealed segments (a year at the default five-minute seal interval is 105,120), one reading each, the 400
series in turn, 79 MB; then an open segment holding five minutes at 45 readings a second, one reading a batch
(13,500 batches). It holds a year's count of seals, not a year's bytes: a sealed segment at the home rate holds about
2.5 MB, which no figure here depends on except through the open segment, which is at full size. On the real file
system, 16 MiB segments.

## Hardware

| Class | Machine | Measured |
|---|---|---|
| Desktop-class (Linux, NVMe, four or more cores, 8 GB or more) | none | not measured here |
| Minimal (1–2 cores, 1–3 GB, SATA SSD or SD card) | none | not measured here |
| Neither | a shared cloud virtual machine (KVM): four cores of a 2.3 GHz server processor, 15 GB, a virtual disk of unknown kind, Linux 6.18; other jobs ran beside it | the figures below |

The machine stands for neither class. It has the desktop class's cores and memory, but they are shared and its
storage is not known to be NVMe; it is far above the minimal class. Its figures are compared with the desktop column
only as an indication. Both classes still need a run on their own hardware (roadmap 9.2).

## Results

Three runs, 2026-11-20, load average about 1 at the start. Each cell gives the median and the worst of the runs of
each of the three runs (S1, S2: 50 runs; S3: 20; S13 empty poll: the mean of 50 polls, five times; S13 visibility:
60 readings). The design's figures are p99 targets.

| # | Shape | Median | Worst | Desktop target | Minimal target |
|---|---|---|---|---|---|
| S1 | 400 latest values, writer's process, nothing written since | 0.16–0.18 ms | 0.33–0.34 ms | ≤ 0.2 ms | ≤ 2 ms |
| S1 | the same, a round of 400 readings since | 0.55–0.67 ms | 1.0–3.7 ms | ≤ 0.2 ms | ≤ 2 ms |
| S2 | another reader handle, nothing since | 0.23–0.34 ms | 0.41–0.91 ms | ≤ 2 ms | ≤ 10 ms |

| S3 | `kvik latest` as a process (warm) | 202–213 ms | 256–278 ms | ≤ 30 ms | ≤ 200 ms (≤ 700 ms cold) |
| S13 | empty poll, a reader handle, `Tail` | 70–78 µs | 77–111 µs | ≤ 50 µs | ≤ 200 µs |

Single empty polls of a reader handle ranged 47 µs to 1.7 ms (the slowest are the full refresh a poll runs once a
second, Q-1017). The first snapshot of a reader just opened took 183–233 ms, and of the writer's reader 206–267 ms.

## Against the targets

- **Met:** S2 in both columns; S13 visibility at both poll intervals; S13's empty poll in the writer's process;
  S1 with nothing written since, by its median (the worst of 50 is above it).
- **Missed on this machine, against the desktop column:** S1 after a write (Q-1007, Q-1055); S3, by six to nine
  times, and near the minimal class's 200 ms (Q-1053); S13's empty poll of a reader process (Q-1054).
- **S3 grows with the number of sealed segments.** An earlier build of the harness, with 1,469 sealed segments of 400 readings each
  and the same open segment, measured S3 at 15 ms (a reader opened) and 21 ms (the process); at 105,687 it is about 195 ms. A one-shot
  reader's start costs about 1.7 µs a sealed segment here.
- **S13's empty poll** was 31–40 µs on about 1,100 sealed segments (Q-1017) and 46–62 µs in that step's re-check on
  a busier moment; on a year of seals it is 64–111 µs across fifteen means.
